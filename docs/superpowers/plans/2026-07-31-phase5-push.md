# Phase 5: Push Notifications — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Register device tokens, and push a notification to a user's phone when they get a DM or are `@mentioned` in a channel — but only if they aren't already connected and watching.

**Architecture:** Device tokens land in a new `device_tokens` table (one row per token; re-registering the same token upserts owner/platform/timestamp rather than erroring). An in-memory `presence.ts` registry — populated straight off the existing per-socket `user:<id>` room join in `sockets/index.ts` — tracks who's currently connected, and `pushService.sendPushToUsers` is the single choke point every caller goes through: it skips online users, batches the rest through firebase-admin's `sendEachForMulticast` at the FCM 500-token ceiling, and garbage-collects any token FCM reports as unregistered. Recipients are computed by extending the existing Phase 2 `message.created` automation event: DM messages push the other member; channel messages push whoever's `@mentioned` (a new lightweight `mentionService.parseMentions` matched against the channel's member list, persisted into the `message_mentions` table that Phase 2 already provisioned but never populated). This keeps push entirely decoupled from the socket/chat send path — exactly the extensibility the automation event bus was built for.

**Tech Stack:** `firebase-admin` ^14 (`sendEachForMulticast`, `messaging/registration-token-not-registered` error code, 500-message batch ceiling — verified against the official `firebase-admin-node` GitHub source, 2026-07-31), `@capacitor/push-notifications` ^8 (`register()`, `requestPermissions()`/`checkPermissions()`, `registration`/`registrationError`/`pushNotificationActionPerformed` listeners, `ActionPerformed.notification.data` — verified against the official Capacitor docs, 2026-07-31).

## Global Constraints

- No web push (VAPID/service worker) this phase — Capacitor native (iOS/Android) only, matching the master plan's scope. The `platform` column/API still accepts `'web'` for forward compatibility, but the frontend only ever registers `'ios'`/`'android'`.
- Every push send goes through `pushService.sendPushToUsers` — the single choke point that (a) filters out users the `presence.ts` registry says are online, (b) chunks tokens at the FCM 500-per-call ceiling, (c) deletes any token FCM reports as `messaging/registration-token-not-registered`. Nothing else calls `admin.messaging()` directly.
- `pushService.ts` no-ops safely whenever `FIREBASE_PROJECT_ID` / `FIREBASE_CLIENT_EMAIL` / `FIREBASE_PRIVATE_KEY` aren't all set — mirrors the existing `lib/cache.ts` no-op-when-unconfigured pattern, so dev/test never needs real Firebase credentials.
- `@mention` parsing is a plain `@DisplayName` case-insensitive, word-boundary match against the sending channel's current member list — no autocomplete/picker UI is added this phase (that's a Phase-2-shaped follow-up); this phase only needs mentions to exist so push has something to target.
- Continue existing conventions: `parseId()` for path params, never chain two `validate()` calls on one route, commits end with `Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>`, verify `npm test`/`tsc` by redirecting to a log file and checking `$?` directly — never pipe through `tail` inside a `&&` chain.
- iOS/Android native wiring (FirebaseMessaging in AppDelegate, `google-services.json`, an actual Firebase project + APNs `.p8`, physical-device delivery) has no SDK or credentials available in this dev environment. Write the code/config exactly as specified below and flag execution/verification as **deferred** — the same standing limitation every prior phase has hit for mobile-specific items.

```ts
// Single-process in-memory registry. If the backend ever scales to multiple
// tasks, this needs to move to a shared store (memcached has no pub/sub, so
// plain presence-per-task plus a shared counter, or a dedicated store, would
// be needed then) — not a concern with the current single-task deployment.
const onlineUsers = new Map<number, number>();

export function markOnline(userId: number): void {
  onlineUsers.set(userId, (onlineUsers.get(userId) ?? 0) + 1);
}

export function markOffline(userId: number): void {
  const count = onlineUsers.get(userId);
  if (count === undefined) return;
  if (count <= 1) onlineUsers.delete(userId);
  else onlineUsers.set(userId, count - 1);
}

export function isOnline(userId: number): boolean {
  return onlineUsers.has(userId);
}

export function filterOffline(userIds: number[]): number[] {
  return userIds.filter((id) => !onlineUsers.has(id));
}
```

```ts
export interface ChannelMemberRef {
  userId: number;
  displayName: string;
}

function escapeRegExp(value: string): string {
  return value.replace(/[.*+?^${}()|[\]\\]/g, '\\$&');
}

export function parseMentions(
  body: string,
  members: ChannelMemberRef[],
  authorUserId: number,
): number[] {
  const matched = new Set<number>();
  for (const member of members) {
    if (member.userId === authorUserId) continue;
    const pattern = new RegExp(`@${escapeRegExp(member.displayName)}(?!\\w)`, 'i');
    if (pattern.test(body)) matched.add(member.userId);
  }
  return [...matched];
}
```

```ts
import { and, eq, inArray } from 'drizzle-orm';
import { db } from '../db/index.js';
import { deviceTokens } from '../db/schema/index.js';

export type Platform = 'ios' | 'android' | 'web';

export async function registerDeviceToken(
  userId: number,
  token: string,
  platform: Platform,
): Promise<void> {
  await db
    .insert(deviceTokens)
    .values({ userId, token, platform, lastSeenAt: new Date() })
    .onDuplicateKeyUpdate({ set: { userId, platform, lastSeenAt: new Date() } });
}

export async function unregisterDeviceToken(userId: number, token: string): Promise<void> {
  await db
    .delete(deviceTokens)
    .where(and(eq(deviceTokens.userId, userId), eq(deviceTokens.token, token)));
}

export async function getTokensForUsers(userIds: number[]): Promise<{ token: string }[]> {
  if (userIds.length === 0) return [];
  return db
    .select({ token: deviceTokens.token })
    .from(deviceTokens)
    .where(inArray(deviceTokens.userId, userIds));
}

export async function deleteToken(token: string): Promise<void> {
  await db.delete(deviceTokens).where(eq(deviceTokens.token, token));
}
```

```ts
import admin from 'firebase-admin';
import { config } from '../config.js';
import { logger } from '../logger.js';
import { deleteToken, getTokensForUsers } from './deviceTokenService.js';
import { filterOffline } from './presence.js';

const FCM_MAX_BATCH_SIZE = 500;

export interface PushPayload {
  title: string;
  body: string;
  channelId: number;
}

let app: ReturnType<typeof admin.initializeApp> | null | undefined;

function getApp(): ReturnType<typeof admin.initializeApp> | null {
  if (app !== undefined) return app;
  if (!config.FIREBASE_PROJECT_ID || !config.FIREBASE_CLIENT_EMAIL || !config.FIREBASE_PRIVATE_KEY) {
    app = null; // push disabled — no Firebase credentials configured
    return app;
  }
  app = admin.initializeApp({
    credential: admin.credential.cert({
      projectId: config.FIREBASE_PROJECT_ID,
      clientEmail: config.FIREBASE_CLIENT_EMAIL,
      privateKey: config.FIREBASE_PRIVATE_KEY.replace(/\\n/g, '\n'),
    }),
  });
  return app;
}

export async function sendPushToUsers(userIds: number[], payload: PushPayload): Promise<void> {
  const firebaseApp = getApp();
  if (!firebaseApp) return; // no-op when unconfigured

  const targetUserIds = filterOffline(userIds);
  if (targetUserIds.length === 0) return;

  const tokens = await getTokensForUsers(targetUserIds);
  if (tokens.length === 0) return;

  const messaging = admin.messaging(firebaseApp);
  for (let i = 0; i < tokens.length; i += FCM_MAX_BATCH_SIZE) {
```

```ts
const MAX_BODY_PREVIEW = 120;

function preview(body: string): string {
  return body.length > MAX_BODY_PREVIEW ? `${body.slice(0, MAX_BODY_PREVIEW)}…` : body;

export function registerPushAutomation(): void {

async function handleMessageCreated(payload: MessageCreatedEvent): Promise<void> {
  const { message, channel } = payload;
  let recipientUserIds: number[];
  if (channel.type === 'dm') {

    title: channel.type === 'dm' ? message.displayName : `${message.displayName} mentioned you`,
    body: preview(message.body),
    channelId: channel.id,
  });
```

```ts
import { Capacitor } from '@capacitor/core';
import { type ActionPerformed, PushNotifications, type Token } from '@capacitor/push-notifications';
import { router } from '@/app/router';
import { api } from './api';

type NativePlatform = 'ios' | 'android';

function nativePlatform(): NativePlatform | null {
  const platform = Capacitor.getPlatform();
  return platform === 'ios' || platform === 'android' ? platform : null;
}

let registeredToken: string | null = null;

export async function initPush(): Promise<void> {
  const platform = nativePlatform();
  if (!platform) return; // web push needs a service worker + VAPID key — out of scope this phase

  const current = await PushNotifications.checkPermissions();
  const granted =
    current.receive === 'granted' ||
    (await PushNotifications.requestPermissions()).receive === 'granted';
  if (!granted) return;

  await PushNotifications.addListener('registration', (token: Token) => {
    registeredToken = token.value;
    api('/api/push/tokens', { method: 'POST', body: { token: token.value, platform } }).catch(() => {
      // best-effort — the next successful register() call will retry
    });
  });

  await PushNotifications.addListener('registrationError', () => {
    // best-effort — user simply won't receive push until the next successful register() call
  });

  await PushNotifications.addListener('pushNotificationActionPerformed', (action: ActionPerformed) => {
    const channelId = action.notification.data?.channelId;
    if (channelId) void router.navigate(`/chat/${channelId}`);
  });

  await PushNotifications.register();
}

export async function teardownPush(): Promise<void> {
  if (!nativePlatform() || !registeredToken) return;
  await api('/api/push/tokens', { method: 'DELETE', body: { token: registeredToken } }).catch(() => {});
  await PushNotifications.removeAllListeners();
  registeredToken = null;
}
```

## Deviations / notes for the implementer

- `messageService.ts`'s `sendMessage` now does one extra `SELECT` (channel members + display names) and, when there are mentions, one extra `INSERT` per send. This is the same cost class as the existing reaction/attachment hydration queries already in this file — no batching concern at this scale.
- `pushAutomation.ts` is deliberately fire-and-forget from `sendMessage`'s perspective (via the existing per-listener error isolation in `events.ts`'s `TypedBus.emit`) — a Firebase outage or a bug in push routing must never block or fail a chat message send. Tests use `vi.waitFor` specifically because of this: the push automation genuinely finishes after `sendMessage`'s promise has already resolved.
- The `platform` enum's `'web'` value is schema/API-only in this phase — no VAPID key, service worker, or browser `Notification` API integration is written. If browser push is wanted later, `pushService.sendPushToUsers` doesn't need to change at all; only a browser-side registration path and (per FCM's web requirements) a service worker would need to be added.
- `getApp()`'s tri-state `undefined | null | App` in `pushService.ts` is intentional: `undefined` means "haven't checked config yet," `null` means "checked, and it's unconfigured — stop checking, always no-op," and a real `App` means "initialized once, reuse it." Don't collapse this to a simple boolean — the whole point is to call `admin.initializeApp` at most once per process.
